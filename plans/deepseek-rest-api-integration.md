# خطة تنفيذ دعم DeepSeek REST API في GenCoder (نسخة تفصيلية احترافية)

**الإصدار:** 2.0  
**التاريخ:** 9 مايو 2026  
**الحالة:** قيد المراجعة  
**المسؤول:** Cline (مساعد برمجي)  
**الجهة المستفيدة:** مستخدمو GenCoder الراغبون في استخدام DeepSeek API  

---

## 1. الملخص التنفيذي

### 1.1 الخلفية
يعتمد GenCoder حالياً على خادم WebSocket مخصص (`deepseek-bridge/ws-server`) للتواصل مع نموذج DeepSeek. هذا الحل غير رسمي، وقد يكون غير مستقر، ولا يدعم الميزات الحديثة مثل دفق الاستجابات القوي، كما يزيد من تعقيد الصيانة.

### 1.2 الهدف الرئيسي
استبدال خادم WebSocket بدعم مباشر لـ **DeepSeek REST API** المتوافقة مع OpenAI، مما يتيح:
- استخدام أحدث نماذج DeepSeek (V3، R1، Coder) بشكل موثوق.
- تحسين تجربة المستخدم من خلال دفق ردود فعل سريع.
- تقليل الاعتماد على مكونات إضافية وتبسيط البنية التحتية.

### 1.3 مؤشرات الأداء الرئيسية (KPIs)
- **زمن الاستجابة للاستدعاء الأول (TTFR)**: أقل من 500 مللي ثانية (متوسط).
- **معدل نجاح الطلبات**: ≥ 99.5% خلال فترة الاختبار.
- **وقت تنفيذ المهمة الكاملة**: تحسن بنسبة 15% على الأقل مقارنة بـ WebSocket.
- **عدد الأسطر البرمجية (LOC) المضافة/المعدلة**: < 500 سطر.
- **تغطية الاختبارات**: ≥ 80% للكود الجديد.

## الملحق: أمثلة على الاستدعاءات

### طلب نموذجي (REST API)
```bash
curl -X POST https://api.deepseek.com/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": true
  }'
```

### مثال استجابة (جزء من الدفق)
```
data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"delta":{"content":"Hello"}}]}
```
